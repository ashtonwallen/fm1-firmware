# CHIP TRACKER

Endless generated chiptune (8-bit console game music) for the M-VAVE FM-1, on fm1-base, built from LOFI RADIO's
tree (itself from AMB-1 Drift: Charles Vestal's AMB-1, MPL-2.0). New engine and UI; AMB-1's platform glue, knob
strip, help cards and screen reader kept. Flashing goes through `../flasher` (its own safety rules); releases are
copied to `flasher/firmware/chip-tracker/X.Y/`.

## Build (WSL Ubuntu)

From Git Bash: `MSYS_NO_PATHCONV=1 wsl.exe -d Ubuntu -- bash -lc 'cd /mnt/d/Projects/FM1/chip-tracker && PYTHON=~/.venvs/fm1/bin/python <cmd>' | tr -d '\0'`

- `./build.sh` dev package `app/build/chiptracker.fwsc` (identity FM-1_9800)
- `./build.sh --release X.Y` release `app/build/chiptracker-X.Y.fwsc` (FM-1_98XXYYZZ); needs `docs/img/screen-tracker.png`
- `./build.sh --host` the simulator; `sh tests/run_tests.sh` all tests (run `./build.sh` first for the update path)
- Engine test modes (build `tests/host/chip_test.c` with `app/dsp/chip.c`, as `tests/run_tests.sh` does):
  no argument runs the checks; `dump STYLE N` prints N songs bar by bar (chords, lead, second pulse, bass, drums)
  for listening on paper; `demos DIR` renders one 20 s WAV per style plus `00-listen.wav` (3 min from power-on)
- Engine cost: time `en_render` on the host against AMB-1 Drift's busiest piece (Low Tide, ~168 ns/frame); the
  busiest style here measures ~66 ns/frame on the same host

Keep LF line endings. No doubles or libm in the engine (fastmath.h). No 64-bit division.

## Where things are

- Engine: `app/dsp/chip.c` / `chip.h`. Parameters (`PARAMS`, `P_*`), instruments (`INS`: volume and duty
  envelopes), modes and Mood weights, progressions (verse/chorus/bridge roles), motifs (16-token strings: chord
  tones, scale steps, cadence targets), styles (`STYLES`: knob recipe, lead and second-pulse instruments and roles,
  bass and drum patterns, intros, forms, echo delay, vibrato, slides, title words), song maker (`en_make_song`:
  patterns 00 intro, 01-03 verse, 04-06 chorus, 07-08 bridge, 09 jingle, plus the order list), player (row and
  frame ticks, effects), voices (polyBLEP pulses, 4-bit triangle, LFSR noise), tone filter, leveller. Commands go
  main to render through a queue; the UI reads `en_*` state. Two song buffers in the pool: the next is made while
  one plays.
- New parameters go at the end of the `P_*` enum, before `P_NPARAMS`; that changes the saved project, so bump
  `PROJ_FORMAT` in `app/app.h` and carry the old format over in `app/project.c`.
- UI: `app/ui.c`. Header, scopes, tracker rows, knob strip; pages Play/Mix/Song; help cards `help_lines`; autosave
  (knobs rested 10 s, settings at most every 5 min, song position at most hourly, only stopped or between songs);
  screen reader `speak`. Pixel font `app/pixfont.h` is generated by `tools/gen_pixfont.py` from Terminus.
- Project: `app/project.c` (format 1, magic "CHT1"); anything else in the store gives the defaults.
- Host checks/commands: `app/host.c`; scenarios in `tests/scenarios/`.
- Words for the screen reader: `app/words.tsv`.
- USB name "CHIP TRACKER FM-1" in `app/fm1.toml`: must keep "FM-1" so M-Flasher finds the unit.
- Names: presets and title words follow `../.claude-briefs/naming-rule.md` (unique across the repo).
