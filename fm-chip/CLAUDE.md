# FM CHIP

Endless generated 16-bit console game music (Mega Drive / Genesis FM style) for the M-VAVE FM-1, on fm1-base, built
from CHIP TRACKER's tree (itself from AMB-1 Drift: Charles Vestal's AMB-1, MPL-2.0). New engine and UI; AMB-1's
platform glue, knob strip, help cards and screen reader kept. Flashing goes through `../flasher` (its own safety
rules); releases are copied to `flasher/firmware/fm-chip/X.Y/`.

## Build (WSL Ubuntu)

From Git Bash: `MSYS_NO_PATHCONV=1 wsl.exe -d Ubuntu -- bash -lc 'cd /mnt/d/Projects/FM1/fm-chip && PYTHON=~/.venvs/fm1/bin/python <cmd>' | tr -d '\0'`

- `./build.sh` dev package `app/build/fmchip.fwsc` (identity FM-1_5200)
- `./build.sh --release X.Y` release `app/build/fmchip-X.Y.fwsc` (FM-1_52XXYYZZ); needs `docs/img/screen-fmchip.png`
- `./build.sh --host` the simulator; `sh tests/run_tests.sh` all tests (run `./build.sh` first for the update path)
- Engine test modes (build `tests/host/fm_test.c` with `app/dsp/fmchip.c`, as `tests/run_tests.sh` does):
  no argument runs the checks; `dump STYLE N` prints N songs bar by bar (chords, lead, duo, bass, drums) for
  listening on paper; `patches [DIR]` measures each patch (peak, brightness, tail) and can write WAVs;
  `cost` times the render per game; `demos DIR` renders one 20 s WAV per game plus `00-listen.wav` (3 min from
  power-on). Set `CLASHES=1` to print each chord-against-lead minor second the checks count.
- Engine cost: time `en_render` on the host against AMB-1 Drift's busiest piece (Low Tide, ~165-175 ns/frame);
  the busiest game here measures ~75-80 ns/frame on the same host (about 0.45x)

Keep LF line endings. No doubles or libm in the engine (fastmath.h). No 64-bit division.

## Where things are

- Engine: `app/dsp/fmchip.c` / `fmchip.h`. Parameters (`PARAMS`, `P_*`), modes and Mood weights, chord qualities
  and progressions (verse/chorus/bridge roles, seventh chords), motifs (16-token strings: chord tones, scale steps,
  cadence targets), bass, drum, hat and fill patterns, `PATCHES` (16 four-operator patches in YM2612 units),
  `STYLES` (13 games: knob recipe, lead/duo/chord/bass patches, duo and chord roles, patterns, register, intro,
  form, echo delay, vibrato, slides, key change, title words), song maker (`en_make_song`: patterns 00 intro,
  01-03 verse, 04-06 chorus, 07-08 bridge, 09 jingle, 10-12 the key-up chorus, plus the order list with `kc_at`),
  voicing (rootless three-voice sevenths, voice-led, avoiding the lead; triads when the seventh clashes), player
  (row and 60 Hz frame ticks, effects), FM (sine table, 8 algorithms, feedback, dB envelopes ticked every 32
  frames), PCM drums (8-bit samples made at init, 11025 Hz), PSG noise hat, tone filter, leveller. Commands go
  main to render through a queue; the UI reads `en_*` state. Two song buffers in the pool.
- New parameters go at the end of the `P_*` enum, before `P_NPARAMS`; that changes the saved project, so bump
  `PROJ_FORMAT` in `app/app.h` and carry the old format over in `app/project.c`.
- UI: `app/ui.c`. Header, register cards (patch, algorithm diagram, operator envelope bars), drum pads, tracker
  rows, knob strip; pages Play/Mix/Song; help cards `help_lines`; autosave (knobs rested 10 s, settings at most
  every 5 min, song position at most hourly, only stopped or between songs); screen reader `speak`.
  Pixel font `app/pixfont.h` is generated by `tools/gen_pixfont.py` from Terminus.
- Project: `app/project.c` (format 1, magic "FMC1"); anything else in the store gives the defaults.
- Host checks/commands: `app/host.c`; scenarios in `tests/scenarios/`.
- Words for the screen reader: `app/words.tsv`.
- USB name "FM CHIP FM-1" in `app/fm1.toml`: must keep "FM-1" so M-Flasher finds the unit.
- Names: games and title words follow `../.claude-briefs/naming-rule.md` (unique across the repo).
